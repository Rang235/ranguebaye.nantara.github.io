Contexte — NTIC CENTER CORPORATION

PME numérique — Saint-Denis (93) — Infrastructure hybride

// Présentation de l'entreprise

NTIC CENTER CORPORATION (NCC) est une entreprise de services du numérique basée à Saint-Denis (93), spécialisée en cybersécurité, cloud computing, infogérance et formation IT. Elle opère sur trois axes géographiques : un datacenter local à Paris, un site distant à Abidjan (connecté par VPN IPSec), et une extension cloud Microsoft Azure pour la sauvegarde et le Plan de Reprise d'Activité.

Dans le cadre de la Mission 2 du Projet d'Étude Professionnel ERIS / IMIE, j'ai participé en tant qu'Administrateur Systèmes & Réseaux Junior à l'extension cloud de l'infrastructure NCC existante, en déployant et administrant l'ensemble de l'environnement Microsoft 365 et Azure.

Problématique : Comment étendre une infrastructure on-premises Windows Server (ncc.local) vers le cloud Microsoft tout en garantissant la continuité de service, la sécurité des identités et la conformité RGPD ?

Entra ID → Noms de domaine personnalisés → Ajouter un domaine personnalisé
Azure CLI

ÉTAPE 03Créer le Resource Group et le Virtual Network

Création du Resource Group NCC-RG-Production et du Virtual Network Azure pour héberger les ressources cloud NCC. Le réseau Azure est segmenté pour permettre le VPN site-to-site vers le datacenter de Paris.

Azure CLI — PowerShell
# Créer le Resource Group principal
az group create \
  --name NCC-RG-Production \
  --location francecentral \
  --tags "Projet=NCC" "Env=Production" "Owner=Ranguebaye.NANTARA"

# Créer le Virtual Network Azure (10.0.0.0/16)
az network vnet create \
  --resource-group NCC-RG-Production \
  --name NCC-VNet-Azure \
  --address-prefix 10.0.0.0/16 \
  --subnet-name NCC-Subnet-Servers \
  --subnet-prefix 10.0.1.0/24 \
  --location francecentral

# Ajouter subnet pour Azure Gateway
az network vnet subnet create \
  --resource-group NCC-RG-Production \
  --vnet-name NCC-VNet-Azure \
  --name GatewaySubnet \
  --address-prefix 10.0.255.0/27

# Vérifier la configuration
az network vnet show --resource-group NCC-RG-Production --name NCC-VNet-Azure --output table
ÉTAPE 04Déployer le VPN Gateway Azure (Site-to-Site)

Configuration de la Azure VPN Gateway pour établir un tunnel VPN IPSec entre le datacenter NCC de Paris (pfSense) et Azure. Cette connexion permet la synchronisation AD Connect et l'accès aux ressources cloud depuis le réseau local.

Azure CLI
# Créer une IP publique pour la gateway
az network public-ip create \
  --resource-group NCC-RG-Production \
  --name NCC-VPN-GW-PIP \
  --allocation-method Static \
  --sku Standard

# Créer la VPN Gateway (VpnGw1 = SKU de base, ~30 min de déploiement)
az network vnet-gateway create \
  --resource-group NCC-RG-Production \
  --name NCC-VPN-Gateway \
  --vnet NCC-VNet-Azure \
  --gateway-type Vpn \
  --vpn-type RouteBased \
  --sku VpnGw1 \
  --public-ip-addresses NCC-VPN-GW-PIP \
  --no-wait

# Créer la Local Network Gateway (représente le site Paris)
az network local-gateway create \
  --resource-group NCC-RG-Production \
  --name NCC-LNG-Paris \
  --gateway-ip-address <IP_PUBLIQUE_PFSENSE_PARIS> \
  --local-address-prefixes 10.10.0.0/16

# Créer la connexion VPN S2S
az network vpn-connection create \
  --resource-group NCC-RG-Production \
  --name NCC-VPN-Paris-to-Azure \
  --vnet-gateway1 NCC-VPN-Gateway \
  --local-gateway2 NCC-LNG-Paris \
  --connection-type IPSec \
  --shared-key "NCC@AzureVPN2024!"

  -Name "svc-adconnect" `

ÉTAPE 02Configurer le suffixe UPN ncc-corp.fr dans l'AD local

Avant la synchronisation, les utilisateurs doivent avoir un UPN matching le domaine vérifié dans Azure. On ajoute le suffixe ncc-corp.fr à l'AD local et on met à jour les UPN des utilisateurs existants.

PowerShell — AD-DC01 (ncc.local)
# Ajouter le suffixe UPN au domaine AD
Get-ADForest | Set-ADForest -UPNSuffixes @{Add="ncc-corp.fr"}

# Vérifier les suffixes disponibles
(Get-ADForest).UPNSuffixes
# ncc-corp.fr

# Mettre à jour le suffixe UPN de tous les utilisateurs existants
Get-ADUser -Filter * -SearchBase "OU=Utilisateurs,DC=ncc,DC=local" | ForEach-Object {
  $newUPN = $_.SamAccountName + "@ncc-corp.fr"
  Set-ADUser $_ -UserPrincipalName $newUPN
  Write-Host "Mis à jour : $newUPN" -ForegroundColor Green
}

# Exemple : ranguebaye.nantara@ncc-corp.fr
# Vérification d'un utilisateur
Get-ADUser -Identity "ranguebaye.nantara" -Properties UserPrincipalName | Select UserPrincipalName
# UserPrincipalName : ranguebaye.nantara@ncc-corp.fr
ÉTAPE 03Activer l'Authentification Multifacteur (MFA) obligatoire

Déploiement du MFA Microsoft Authenticator pour l'ensemble des utilisateurs NCC via une politique d'accès conditionnel. Le MFA est imposé pour tous les accès M365 et Azure, avec exclusion des comptes de service.

Entra ID → Sécurité → Accès conditionnel → Nouvelle stratégie
Microsoft Graph PowerShell
# Connexion à Microsoft Graph avec les droits nécessaires
Connect-MgGraph -Scopes "Policy.ReadWrite.ConditionalAccess", "Application.Read.All"

# Créer la politique d'accès conditionnel MFA obligatoire
$policy = @{
  displayName = "NCC-CA-MFA-AllUsers"
  state = "enabled"
  conditions = @{
    users = @{
      includeUsers = @("All")
      excludeGroups = @("<ID_GROUPE_COMPTES_SERVICE>")
    }
    applications = @{
      includeApplications = @("All")
    }
    clientAppTypes = @("all")
  }
  grantControls = @{
    operator = "OR"
    builtInControls = @("mfa")
  }
}
New-MgIdentityConditionalAccessPolicy -BodyParameter $policy

# Vérifier les politiques d'accès conditionnel actives
Get-MgIdentityConditionalAccessPolicy | Select-Object DisplayName, State | Format-Table
# NCC-CA-MFA-AllUsers    enabled

ÉTAPE 01Attribution des licences Microsoft 365 E3

Attribution des licences Microsoft 365 E3 aux 50 utilisateurs NCC via PowerShell. Les licences sont assignées par groupe AD synchronisé pour automatiser l'attribution lors des arrivées/départs.

Microsoft Graph PowerShell
# Connexion
Connect-MgGraph -Scopes "User.ReadWrite.All", "Directory.ReadWrite.All"

# Voir les SKU disponibles dans le tenant
Get-MgSubscribedSku | Select-Object SkuPartNumber, ConsumedUnits, @{N="Total";E={$_.PrepaidUnits.Enabled}} | Format-Table
# SPE_E3    (Microsoft 365 E3)    12 / 50

# Récupérer l'ID du SKU M365 E3
$skuId = (Get-MgSubscribedSku | Where-Object SkuPartNumber -eq "SPE_E3").SkuId

# Attribuer la licence à tous les membres du groupe NCC-AllUsers
$groupMembers = Get-MgGroupMember -GroupId "<ID_GROUPE_NCC_ALLUSERS>"
foreach ($member in $groupMembers) {
  Set-MgUserLicense -UserId $member.Id `
    -AddLicenses @{SkuId = $skuId} `
    -RemoveLicenses @()
  Write-Host "Licence M365 E3 attribuée à : $($member.Id)" -ForegroundColor Green
}

# Vérifier les licences d'un utilisateur
Get-MgUserLicenseDetail -UserId "ranguebaye.nantara@ncc-corp.fr" | Select-Object SkuPartNumber, ServicePlans

ÉTAPE 02Configurer les politiques DLP — Protection des données sensibles

Création de politiques de Data Loss Prevention (DLP) via Microsoft Purview pour détecter et bloquer le partage non autorisé de données sensibles NCC (données clients, informations de paiement, données personnelles RGPD).

Microsoft Purview → Protection des informations → Stratégies DLP
Security & Compliance PowerShell
# Connexion au centre de conformité
Connect-IPPSSession -UserPrincipalName admin@ncc-corp.fr

# Créer une politique DLP pour protéger les données personnelles (RGPD)
New-DlpCompliancePolicy -Name "NCC-DLP-RGPD" `
  -ExchangeLocation All `
  -SharePointLocation All `
  -OneDriveLocation All `
  -TeamsLocation All `
  -Mode Enable

# Ajouter une règle : bloquer le partage de numéros de carte bancaire
New-DlpComplianceRule -Name "NCC-DLP-CarteBancaire" `
  -Policy "NCC-DLP-RGPD" `
  -ContentContainsSensitiveInformation @{Name="Credit Card Number"; minCount=1} `
  -BlockAccess $true `
  -NotifyUser "SiteAdmin","LastModifiedBy" `
  -GenerateIncidentReport "SiteAdmin" `
  -IncidentReportContent "All"

# Règle : protéger les numéros de sécurité sociale (RGPD France)
New-DlpComplianceRule -Name "NCC-DLP-NSS-France" `
  -Policy "NCC-DLP-RGPD" `
  -ContentContainsSensitiveInformation @{Name="France Social Security Number"; minCount=1} `
  -BlockAccess $true `
  -NotifyUser "SiteAdmin"

# Vérifier les politiques DLP actives

ÉTAPE 01Créer le Recovery Services Vault

Le Recovery Services Vault est le coffre de sauvegarde Azure qui centralise toutes les sauvegardes NCC (serveurs on-premises et ressources Azure). Localisation : France Central pour respecter la souveraineté des données.

Azure CLI
# Créer le Recovery Services Vault
az backup vault create \
  --resource-group NCC-RG-Production \
  --name NCC-Backup-Vault \
  --location francecentral
